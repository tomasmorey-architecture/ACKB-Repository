
# Part IV — Memory Architecture

Memory constitutes the persistent cognitive substrate of the Architectural Knowledge Base.

Its purpose extends far beyond data storage.

Memory preserves architectural understanding, reasoning processes, interpretative frameworks, design knowledge and organizational experience accumulated throughout the lifetime of an architectural practice.

Unlike conventional information systems, ACKB models memory as a hierarchical cognitive architecture in which different levels preserve knowledge with different temporal horizons, scopes and responsibilities.

Each memory level contributes to the continuous construction of architectural intelligence while maintaining semantic consistency across the entire repository.

Together, these memory layers enable architectural knowledge to evolve from individual observations into long-term organizational learning.

---

# 10. Memory Architecture

ACKB defines a hierarchical memory model composed of multiple cognitive layers.

Each layer represents a different level of abstraction, permanence and applicability.

Knowledge may progressively migrate between memory levels as its relevance evolves.

The hierarchy is designed to maximize knowledge reuse while preserving project specificity and historical traceability.

---

## 10.1 Universal Memory

Universal Memory contains architectural knowledge considered independent of any particular organization or project.

It represents globally reusable knowledge that remains stable over long periods of time.

Typical contents include:

- architectural theory;
- structural principles;
- environmental knowledge;
- construction systems;
- historical knowledge;
- mathematical models;
- physical principles;
- publicly available regulations;
- standardized ontologies.

Universal Memory serves as the cognitive foundation upon which all other memory levels build.

It evolves slowly and provides stable conceptual references for architectural reasoning.

---

## 10.2 Studio Memory

Studio Memory represents the collective intelligence accumulated by an architectural practice.

Unlike Universal Memory, Studio Memory reflects the identity, methodology and experience of a particular organization.

Typical contents include:

- office methodology;
- design principles;
- organizational standards;
- recurring workflows;
- validated best practices;
- lessons learned;
- reusable design strategies;
- agent profiles;
- governance policies;
- organizational frameworks.

Studio Memory transforms experience into long-term organizational knowledge.

Its primary objective is to ensure that every completed project strengthens the intellectual capital of the practice.

---

## 10.3 Project Memory

Project Memory contains all knowledge associated with a single architectural project.

It represents the complete cognitive history of the project rather than merely its documentation.

Project Memory may include:

- project context;
- place models;
- interpretative frameworks;
- design frameworks;
- hypotheses;
- decisions;
- references;
- analyses;
- design strategies;
- architectural concepts;
- generated outputs.

Project Memory evolves continuously throughout the design process and constitutes the principal workspace for architectural reasoning.

Upon project completion, selected knowledge may be promoted into Studio Memory.

---

## 10.4 Workspace Memory

Workspace Memory represents temporary collaborative environments created around specific activities.

A workspace may correspond to:

- a design phase;
- a competition;
- a workshop;
- a multidisciplinary collaboration;
- a simulation;
- an experimental investigation.

Workspace Memory enables focused collaboration without affecting the stability of the broader Project Memory.

Knowledge generated within workspaces may later be consolidated into permanent memory levels.

---

## 10.5 Session Memory

Session Memory preserves the cognitive context of an individual interaction.

Its purpose is to maintain continuity during a specific reasoning process.

Session Memory typically includes:

- active conversations;
- temporary reasoning chains;
- current objectives;
- intermediate conclusions;
- unresolved questions;
- active hypotheses.

Session Memory exists only for the duration of a cognitive session.

Relevant knowledge produced during the session may subsequently be incorporated into Project Memory.

---

## 10.6 Working Memory

Working Memory represents the active cognitive space used by both human architects and AI agents while reasoning.

Unlike persistent memory, Working Memory is intentionally dynamic.

It contains only the knowledge immediately required for current reasoning.

Typical contents include:

- active context;
- selected Knowledge Objects;
- active Interpretative Frameworks;
- active Design Frameworks;
- current constraints;
- current opportunities;
- reasoning state;
- temporary hypotheses.

Working Memory is continuously reconstructed by the Project Coordinator according to the needs of each task.

This selective activation minimizes cognitive overload while maximizing reasoning quality.

Working Memory should therefore be understood as a dynamic cognitive view of the repository rather than an independent storage layer.

---

## Memory Hierarchy

The complete hierarchy can be represented as follows:

```text
Universal Memory
        │
        ▼
Studio Memory
        │
        ▼
Project Memory
        │
        ▼
Workspace Memory
        │
        ▼
Session Memory
        │
        ▼
Working Memory
```

Knowledge generally flows downward during reasoning and upward during organizational learning.

This bidirectional evolution enables ACKB to balance project specificity with long-term knowledge preservation.

# 11. Memory Synchronization

Memory levels cannot evolve independently.

Architectural knowledge generated at one level frequently influences the others.

Memory Synchronization defines the mechanisms through which knowledge remains coherent across the complete memory hierarchy.

Synchronization should preserve semantic consistency while avoiding unnecessary duplication.

---

## 11.1 Synchronization Principles

Synchronization follows several fundamental principles.

### Progressive Consolidation

Knowledge should move toward more persistent memory levels only after sufficient validation.

Temporary observations should not immediately become organizational knowledge.

---

### Selective Promotion

Only reusable knowledge should be promoted beyond Project Memory.

Project-specific details should remain within their original context unless broader applicability has been demonstrated.

---

### Context Preservation

Whenever knowledge is transferred between memory levels, its original context shall remain traceable.

Knowledge must never lose the circumstances under which it was created.

---

### Bidirectional Learning

Higher memory levels provide reusable knowledge to projects.

Completed projects enrich higher memory levels through validated experience.

This continuous feedback loop enables organizational learning.

---

### Version Awareness

Synchronization shall preserve historical continuity.

Updated knowledge should extend previous understanding rather than overwrite it.

---

## 11.2 Synchronization Events

Typical synchronization events include:

- promotion of validated project knowledge into Studio Memory;
- incorporation of new regulations into Universal Memory;
- creation of reusable design methodologies;
- extraction of lessons learned;
- publication of organizational standards;
- retirement or archival of obsolete knowledge.

Synchronization events should remain fully traceable.

---

# 12. Memory Governance

Memory Governance defines the policies that regulate the creation, modification, validation and long-term preservation of architectural memory.

Its objective is to ensure that ACKB remains a coherent and trustworthy cognitive system throughout decades of continuous evolution.

Governance applies equally to human contributors and artificial intelligence agents.

---

## 12.1 Persistence Policies

Each memory level possesses distinct persistence requirements.

Governance defines:

- retention policies;
- archival criteria;
- deletion restrictions;
- promotion rules;
- ownership responsibilities.

Knowledge should only become persistent after appropriate validation.

---

## 12.2 Consistency Policies

Semantic consistency constitutes a fundamental requirement of ACKB.

Governance mechanisms should prevent:

- duplicated knowledge;
- conflicting definitions;
- ambiguous terminology;
- broken semantic relationships;
- inconsistent metadata.

Consistency should be continuously monitored throughout repository evolution.

---

## 12.3 Evolution Policies

Architectural knowledge evolves continuously.

Governance therefore regulates:

- version creation;
- reinterpretation;
- framework evolution;
- knowledge consolidation;
- historical preservation.

Previous knowledge should remain accessible whenever possible.

Evolution is considered an extension of knowledge rather than its replacement.

---

## 12.4 Roles and Responsibilities

Memory Governance distinguishes several cognitive responsibilities.

Examples include:

- architects;
- Project Coordinators;
- specialized AI agents;
- Knowledge Manager;
- organizational reviewers.

Although many agents may generate knowledge, persistent modifications to the repository should only occur through governed workflows that preserve consistency, traceability and semantic integrity.

---

## 12.5 Cognitive Integrity

The ultimate objective of Memory Governance is the preservation of cognitive integrity.

Every modification to the repository should strengthen the collective architectural intelligence of the organization rather than simply increasing the quantity of stored information.

Memory is therefore understood as a continuously evolving representation of architectural understanding.

Maintaining its coherence, reliability and interpretability is essential to the long-term success of ACKB.
