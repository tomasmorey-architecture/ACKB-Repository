
# Part VII — Reasoning Architecture

Architectural reasoning is inherently distributed.

No single architect, document or artificial intelligence model possesses all the knowledge required to understand a complex architectural project.

ACKB therefore models reasoning as a collaborative cognitive process performed by multiple specialized agents operating over a shared Architectural Knowledge Base.

Each agent contributes domain-specific expertise while maintaining complete semantic interoperability through the common Cognitive Core.

Rather than replacing human judgement, the Reasoning Architecture augments architectural thinking by organizing, coordinating and synthesizing multiple complementary reasoning processes.

The result is a form of collective architectural cognition in which understanding progressively emerges from collaboration rather than isolated computation.

---

# 16. Reasoning Engine

The Reasoning Engine defines the abstract cognitive model through which human architects and AI agents transform knowledge into architectural understanding.

It does not prescribe specific algorithms, language models or implementation technologies.

Instead, it defines the conceptual principles governing architectural reasoning throughout ACKB.

Reasoning is understood as an iterative cognitive activity driven by goals, context, interpretation and reflection.

Every reasoning process shall preserve explainability, traceability and semantic consistency.

---

## 16.1 Purpose

The purpose of the Reasoning Engine is to support architectural thinking rather than automate architectural design.

It assists architects by:

- organizing relevant knowledge;
- constructing contextual understanding;
- identifying relationships;
- generating hypotheses;
- evaluating alternatives;
- supporting decision-making;
- detecting inconsistencies.

Architectural creativity remains a human responsibility.

The Reasoning Engine provides cognitive support.

---

## 16.2 Contextual Reasoning

Architectural reasoning is always contextual.

The same Knowledge Object may lead to different conclusions depending on:

- project goals;
- environmental conditions;
- historical context;
- active Interpretative Frameworks;
- Design Frameworks;
- current design phase;
- client priorities.

The Reasoning Engine therefore operates over dynamically constructed Working Memory rather than the entire repository.

Context construction is considered one of the principal responsibilities of the Project Coordinator.

---

## 16.3 Progressive Reasoning

Architectural reasoning rarely produces immediate conclusions.

Instead, understanding develops progressively through successive cycles of:

- observation;
- interpretation;
- hypothesis generation;
- evaluation;
- reflection;
- refinement.

The Reasoning Engine explicitly supports iterative reasoning.

Every reasoning cycle contributes additional knowledge to the repository.

---

## 16.4 Explainable Reasoning

Every reasoning process should remain reconstructable.

The repository preserves:

- activated knowledge;
- supporting references;
- interpretative frameworks;
- design frameworks;
- intermediate hypotheses;
- rejected alternatives;
- final conclusions.

Reasoning therefore becomes a persistent organizational asset rather than a transient computational activity.

---

# 17. Multi-Agent Reasoning

ACKB models architectural reasoning as a collaborative activity performed by multiple specialized cognitive agents.

Each agent possesses a distinct area of expertise while sharing a common cognitive language.

Agents do not operate independently.

They collaborate continuously through the shared Architectural Knowledge Base.

The Project Coordinator orchestrates this collaboration by constructing Working Memory, delegating reasoning tasks and integrating the resulting knowledge.

---

## 17.1 Project Coordinator

The Project Coordinator is the principal cognitive orchestrator of an architectural project.

Rather than performing every reasoning task itself, it coordinates specialized reasoning across the agent ecosystem.

Its responsibilities include:

- maintaining project objectives;
- constructing Working Memory;
- selecting relevant knowledge;
- activating Interpretative Frameworks;
- activating Design Frameworks;
- delegating reasoning tasks;
- integrating specialized conclusions;
- preserving cognitive coherence.

The Project Coordinator represents the persistent cognitive identity of the project throughout its lifecycle.

---

## 17.2 Reference Agent

The Reference Agent manages architectural knowledge originating from external sources.

Its responsibilities include:

- analysing bibliographic references;
- extracting Knowledge Objects;
- identifying Reference Intent;
- proposing Interpretative Frameworks;
- detecting conceptual relationships;
- enriching Project Memory.

Rather than merely retrieving information, the Reference Agent preserves the intellectual motivations underlying architectural references.

---

## 17.3 Place Analysis Agent

The Place Analysis Agent constructs progressively richer representations of architectural context.

Its reasoning integrates:

- GIS information;
- environmental analysis;
- topography;
- climate;
- historical evolution;
- cultural context;
- landscape characteristics;
- ecological systems.

The principal output of the agent is not raw analysis but a structured Place Model capable of supporting subsequent interpretation.

The Place Analysis Agent therefore transforms geographical information into architectural understanding.

---

## 17.4 Strategy Agent

The Strategy Agent synthesizes interpretation into architectural direction.

Its responsibilities include:

- evaluating project intentions;
- identifying opportunities;
- comparing strategic alternatives;
- generating architectural strategies;
- maintaining consistency between Design Frameworks and project objectives.

The Strategy Agent does not generate architectural form.

It organizes architectural direction.

---

## 17.5 Sketch Agent

The Sketch Agent explores architectural possibilities through visual reasoning.

Rather than producing final representations, it supports conceptual exploration.

Typical outputs include:

- conceptual sketches;
- spatial diagrams;
- structural explorations;
- organizational schemes;
- iterative visual hypotheses.

Sketches constitute cognitive artifacts that stimulate architectural reflection rather than finished design products.

---

## 17.6 Compliance Agent

The Compliance Agent evaluates architectural proposals against external requirements.

Typical responsibilities include:

- regulatory verification;
- planning compliance;
- accessibility;
- environmental standards;
- structural constraints;
- documentation consistency.

Compliance reasoning complements, but never replaces, architectural judgement.

---

## 17.7 Additional Specialized Agents

ACKB intentionally supports an extensible ecosystem of specialized cognitive agents.

Examples include:

- Material Agent;
- Structural Agent;
- Environmental Simulation Agent;
- Cost Analysis Agent;
- Heritage Agent;
- Construction Agent;
- Documentation Agent;
- BIM Integration Agent;
- Rendering Agent;
- Knowledge Ingestion Agent.

Every specialized agent shall reason according to the common Cognitive Core while preserving semantic interoperability with the rest of the repository.

---

## Collective Architectural Cognition

The primary objective of Multi-Agent Reasoning is not task distribution.

Its objective is the construction of **Collective Architectural Cognition**.

Collective Architectural Cognition emerges when multiple specialized reasoning processes interact through shared knowledge, common interpretative frameworks and coordinated architectural intentions.

The resulting understanding exceeds the capabilities of any individual agent.

Architectural intelligence therefore becomes an emergent property of collaboration.

---

# 18. Reflection

Architectural reasoning is inherently reflective.

Design advances through continuous evaluation of previous assumptions rather than through linear problem solving.

ACKB therefore models Reflection as a first-class cognitive process.

Reflection continuously improves both architectural understanding and organizational knowledge.

---

## 18.1 Self-Critique

Every significant reasoning process should be capable of evaluating its own conclusions.

Self-critique examines:

- logical consistency;
- unsupported assumptions;
- conceptual coherence;
- alignment with project goals;
- completeness of reasoning.

Reflection should strengthen architectural quality without suppressing creativity.

---

## 18.2 Alternative Hypotheses

Architectural reasoning rarely possesses a single correct solution.

Reflection therefore encourages the explicit generation of alternative hypotheses.

Alternative hypotheses:

- challenge existing assumptions;
- expand the design space;
- reveal hidden opportunities;
- improve conceptual robustness.

ACKB preserves rejected hypotheses as valuable components of organizational learning.

---

## 18.3 Knowledge Gap Detection

Reflection continuously identifies areas where available knowledge is insufficient.

Typical knowledge gaps include:

- missing references;
- incomplete environmental analysis;
- unresolved structural questions;
- uncertain regulations;
- conflicting interpretations.

Detected gaps become explicit cognitive objects that may trigger additional reasoning tasks or activate specialized agents.

Knowledge gaps therefore guide future exploration rather than representing failures.

---

## 18.4 Continuous Learning

Reflection transforms experience into organizational intelligence.

Lessons emerging from completed reasoning cycles may contribute to:

- Project Memory;
- Studio Memory;
- Interpretative Frameworks;
- Design Frameworks;
- organizational methodologies;
- future reasoning strategies.

Continuous learning enables ACKB to become progressively more capable over time without losing historical knowledge.

---

## The Architectural Reasoning Cycle

The complete reasoning architecture established by ACKB can be summarized as the following continuous cognitive cycle:

```text
Goal
    │
    ▼
Context Construction
    │
    ▼
Working Memory
    │
    ▼
Multi-Agent Reasoning
    │
    ▼
Interpretation
    │
    ▼
Design Frameworks
    │
    ▼
Strategy
    │
    ▼
Concept
    │
    ▼
Architectural Proposal
    │
    ▼
Reflection
    │
    ▼
Knowledge Consolidation
    │
    ▼
Updated Memory
```

Rather than representing a linear workflow, this cycle illustrates the continuous evolution of architectural understanding.

Each iteration enriches the Architectural Knowledge Base, strengthening both the current project and the long-term cognitive capabilities of the architectural practice.
